# 引用真实性核验（含撤稿检查）

帮你回答投稿前最要命的问题：**我引的文献都是真的吗？有没有引到已撤稿的论文？**

行业实测：主流大模型生成的引用中 78%–90% 是编造的；仅 2025 年全球就产生约 14.7 万条虚构引用。本技能用**确定性脚本**（不是让 AI 猜）逐条查询权威数据库，把结果摆出来。

## 能力与边界（先读这一段）

**做**：核验引用是否真实存在（DOI 直查 / 标题+作者+年份交叉匹配）、检查撤稿状态、发现元数据出入（年份/作者/题名）、输出逐条报告。

**不做**：
- ❌ 不替代人工判断——「已核实」是数据库命中，不是绝对真实；
- ❌ 不判「是否抄袭」，不提供查重；
- ❌ 不下载任何文献全文，只查元数据；
- ❌ **绝不编造核验结果**——所有结论必须来自脚本输出，脚本没查到的就是「未能核实」。

## 工作流程

### 第 1 步 · 拿到参考文献清单

- 用户给了文件（PDF / DOCX / TEX / Markdown）→ 用你自己的文件读取能力，抽出「References / 参考文献 / Bibliography」章节；
- 用户直接贴了引用 → 原样使用；
- 整理成**每行一条引用**的纯文本（保留行首编号 [1] 没关系，脚本会处理）。

清单超过 100 条时，分批处理（每批 50 条），最后合并汇报。

### 第 2 步 · 运行核验脚本

把清单写入临时文件（如 `refs.txt`），然后运行本技能目录下的脚本：

```bash
python scripts/verify_citations.py refs.txt -o 引用核验报告.md
```

- 只需 Python 3.9+，**无第三方依赖**；
- 联网查询 OpenAlex + Crossref（均免费、无需 API Key）；
- 并发查询，30 条引用约 1 分钟内完成；
- 如需以自己的邮箱进入 OpenAlex「礼貌池」（更稳的速率），设环境变量
  `CITATION_VERIFY_MAILTO=你的邮箱` 后再运行。

### 第 3 步 · 读取报告并向用户汇报

读生成的 Markdown 报告，按下面的优先级向用户汇报（**严重问题永远放最前面**）：

| 顺序 | 状态 | 怎么说 |
|---|---|---|
| 1 | 🚨 **已撤稿** | 醒目警示：给出撤稿通知信息，建议立即替换或删除该引用——「引用已撤稿论文可能造成严重学术问题」 |
| 2 | ❌ **DOI 查无此文（疑似编造）** | 明确告知两条数据库都查无此文，请用户回到原文核对；常见于 AI 生成的参考文献 |
| 3 | ⚠️ **DOI 未收录 / 元数据差异**（年份不符、作者对不上、题名相似度低） | 逐条列出差异，建议用户核对是否抄写错误 |
| 4 | ❓ **未能核实** | 如实说明：图书与中文文献常不在数据库收录范围，属正常现象，不是判定引用有假 |
| 5 | ✅ **已核实** | 汇总数即可；提醒「已核实 ≠ 无需检查」 |

汇报时**必须带上口径**（报告已算好）：
- 口径一：可核实引用中确认真实存在的比例；
- 口径二：被标注「未能核实」的比例。

### 第 4 步 · 收尾

- 把报告文件路径告诉用户，方便其留存或导出；
- 用户要求修改引用（如补 DOI、改年份）时可以协助，但**重新核验必须重跑脚本**，不要凭记忆给结论。

## 判断规则（脚本内置，了解即可）

- **有 DOI**：先 OpenAlex 直查（`is_retracted` 判撤稿），404 转 Crossref 直查；两库都 404 时**再做严格标题匹配**（相似度 ≥0.65 且需作者/年份锚点），匹配到同题文献则报「DOI 未收录」，否则才报「疑似编造」——不轻易冤枉；
- **无 DOI**：标题+作者+年份交叉匹配（OpenAlex 标题检索 + Crossref 书目检索），要求至少 2 个作者姓氏命中、或 1 个姓氏+年份精确一致，否则一律「未能核实」；
- 撤稿细节（撤稿通知 DOI、日期、来源）取自 Crossref 的 Retraction Watch 数据。

## 隐私说明（用户可能问）

脚本只把**每条引用本身的文本**（DOI、题名、作者、年份）发往 OpenAlex / Crossref 两个学术元数据公开接口；稿件全文不出本机。查询结果会在本技能目录下缓存 30 天（`.verify_cache.json`），删除该文件即清除。
