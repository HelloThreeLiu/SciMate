### 1.2 新增内容的质量评价

**10.4「生成式 AI 合规立场」——本轮最有价值的新增。** 三段结构（为什么选 BYOK / 五条自我约束 / 必须承认的边界）里，第三段「不要对外说过头」（「这不是法律意见」「需专业人士确认」「按季度复核」）最难写也最可贵——多数产品文档只写立场不写边界。它把 5.11 那句孤零零的主张变成了有论证、有出处、有自限的一节，BYOK 策略的合规地基从「声称」变成了「成立」。

**spike 清单——把「开工前提」从口号变成了可勾选的验收。** 尤其两处自我修正：① 指出「含 C 扩展依赖」在阶段一无对象（内核轻量、无沙箱），真正要量的是 pandoc 与 Python 运行时；② 给「不可接受时」各配了处置动作。第 1–2 周做完这件事，「桌面方案要不要重谈」就有了明确答案。

**阶段零两项度量——产品级风险从「识别」走到「可测」。** 且「兜底方案与 5.11 立场冲突、必须阶段零一并定」这句话，把最容易被拖延的决策提前钉死了。这是整个 V1.9 里对项目存活率贡献最大的一处。

**12.3 的 B4 / B5 / C6** 把剩余开放项（签名证书个人采购、度量落地、macOS 时点）全部显式化——至此**文档里不再有「隐含的未决事项」**，所有开放问题都在 12.3 里有一行。

## 三、本轮新发现（2 处表述级 + 2 条建议）

V1.9 全文档扫描（含内部引用、计数、格式）的结果：**无结构性、无执行级问题，仅剩以下 4 条。**

### 发现 1 ⚠️ 文档结尾的版本引用，当天第三次过时（L2073）

结尾写「本版依据两份外部文档修订：《…可行性评估报告》**V1.0** 与《…逐条核对结果》**V1.0**」——而 V1.9 实际依据的是两者的 **V2.0**；配套文档行（L11）也只列了《核对结果》V2.0、未列《评估报告》。

这是「**版本号写死 → 过时**」模式当天第三次出现：V1.6/V1.7/V1.8 归档表述连错两版 → V1.9 刚用「去版本号」的写法修掉它，并在教训里写下「让结构兜住，不靠记忆」→ **同一版里，结尾引用又犯了一次**。修法同款：改为「依据两份外部评估/核对文档的最新版（见 outputs/）」，或在配套文档行补齐《评估报告》并随版同步。十分钟。

### 发现 2 ⚠️ 「16 处 vs 11 处」两套计数口径对不上（L21 vs L90）

文档头（L21）：「共 **16 处**（报告 8 条 + 小瑕疵 3 条 + 核对补充 5 处）」；修订记录（L90）：「① 修净 **11 处** 文档缺陷：4 + 3 + 4」。两套数字各自成理，但对不上账：① 的 11 项**漏列了 5 处实际修复**（spike 清单、阶段二产能、招募筛选、并行线口径、C-2 表述——部分散在 ②③ 里但没入账），且「8+3+5=16」的等式**数值上成立、组成上不真**（实际构成是：报告 7 条〔BYOK 单列为度量〕+ 小瑕疵 3 + 核对 4〔A3 并入 A 组〕+ V1.9 自查 2〔并行线、C-2〕）。

**不改变任何实质，但这是「统计要重算，不要手写」这条教训在自家修订记录上的复现**——正是 V1.6 用 12.2 的四版错数换来的那条。建议修订记录直接复用文档头的四类分账，一处维护。

### 建议 1（度量）给「配 Key 成功率」补两个定义

阶段零表单（L1117）问「你在这 7 天内成功配置了至少一个模型密钥吗」——**7 天从何时起算**（建议：安装技能当日）没有锚点；**「明显低于预期」的预期值**也没有定义（建议给一条触发线，例如 < 40% 即启动兜底评估、并同步决策 5.11 立场）。另外这是自报式数据，收数时顺带记录「未回复」占比，避免把沉默当成功。

### 建议 2（合规）10.4 的季度复核清单点名一项新规

《人工智能生成合成内容标识办法》（2025 年 9 月起施行）对「生成内容标识」的义务边界仍在演化，建议在 10.4 的「按季度复核」里留个名字。好消息是方向已经对齐：M3-7 / 5.8 早已承诺「AI 生成内容带明确标识」——产品行为与监管方向一致，缺的只是把这件事记入复核清单。
